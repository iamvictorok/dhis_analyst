# DHIS2 Public Health Intelligence Assistant

Conversational public health analytics for DHIS2. The implementation follows the consolidated spec in `dhis2-ai-analyst-spec.md` and ships all major surfaces at once: streaming chat, deterministic local agent fallback, DHIS2 Analytics API adapter, metadata search/sync contract, evidence tags, report/dashboard/presentation/export outputs, standalone auth, and a no-build static frontend.

> **Presenting it?** See the step-by-step live demo script: [docs/DEMO.md](docs/DEMO.md).

## Run Backend

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r backend\requirements.txt
.\.venv\Scripts\python -m uvicorn backend.main:app --reload --reload-dir backend --host 127.0.0.1 --port 8000
```

## Run Frontend

The project can be run in two modes:

### Production / Consolidated Mode (Default)
Start the backend using the command above and open:
```text
http://127.0.0.1:8000/
```
The backend serves the pre-built static assets from `frontend/dist/`.

### Development Mode
For a hot-reloading development experience:
1. Run backend (above).
2. Start the frontend development server:
   ```powershell
   cd frontend
   npm install
   npm run dev
   ```
3. Open `http://localhost:5173/` in your browser. It will proxy requests to the backend server.

## Run with a hosted model (Gemini) against the public DHIS2 demo

Copy `.env.example` to `.env` and set:

```env
DEPLOYMENT_MODE=standalone
DHIS2_BASE_URL=https://play.im.dhis2.org/stable-2-41-10   # check it is up: /api/system/info.json
DHIS2_SERVICE_ACCOUNT_USER=admin                          # public demo credentials only
DHIS2_SERVICE_ACCOUNT_PASS=district
LLM_PROVIDER=gemini
LLM_MODEL=gemini/gemini-flash-latest                      # or another current Gemini model
LLM_API_KEY=<your Google AI Studio key>                   # never commit this
LLM_TIMEOUT_SECONDS=90
JWT_SECRET=<long random string>
STANDALONE_ACCESS_CODE=<password for anyone you share a hosted URL with>
```

Then rebuild the frontend once (`cd frontend && npm install && npm run build`) and start the backend.
Behind a corporate/HTTP proxy, also set `DISABLE_AIOHTTP_TRANSPORT=True` (LiteLLM's default
aiohttp transport ignores `HTTPS_PROXY`). The app only issues GET requests to DHIS2.

## DHIS2 failover: live → fallback → cached demo snapshot

Public demo instances go down without warning, so the app picks its data source at
startup and re-checks every `DHIS2_HEALTH_INTERVAL_SECONDS` (default 60):

| Header dot | Meaning |
| --- | --- |
| 🟢 **Live** | the primary instance (first of `DHIS2_BASE_URLS`) answered its health check |
| 🟡 **Fallback** | primary down; another instance in `DHIS2_BASE_URLS` is serving (answers show a "Fallback DHIS2 instance" badge) |
| 🟠 **Cached** | every instance down and `DHIS2_SNAPSHOT_MODE=auto`: answers come from `backend/demo_snapshot/dhis2_snapshot.json` and are labelled **"Cached data as of <date>"** (chat, report banner, Excel Sources sheet) |
| 🔴 **Offline** | everything down and the snapshot is off/missing |

The snapshot holds the DHIS2 metadata pages plus the Analytics responses behind the
suggested demo questions (`backend/demo_snapshot/demo_questions.json`). A question
outside it, while cached, gets a clear "not in the offline demo snapshot" message.
Re-record it shortly before a demo (needs the live primary instance and an LLM):

```bash
python scripts/record_demo_snapshot.py   # merges into the existing file
git add backend/demo_snapshot/dhis2_snapshot.json && git commit -m "chore: refresh demo snapshot"
```

`DHIS2_SNAPSHOT_MODE=always` forces cached mode for an offline rehearsal; `off` disables it.
The status is at `GET /api/dhis2/status` (public, no secrets).

## Deploy on Render (free plan, one web service)

The repo ships a `render.yaml` Blueprint and a root `Dockerfile`: the image builds the
frontend (`npm ci && npm run build`) and FastAPI serves it, so there is one service.

1. **Repo access.** Render must be able to read this GitHub repo: connect your GitHub
   account in Render (Account → GitHub) and grant it access to `dhis_analyst`
   (needed even for a public repo if you want auto-deploys).
2. **Create.** Render dashboard → **New → Blueprint** → pick the repo → branch `main`
   (or the PR branch to test before merging) → Render reads `render.yaml`.
3. **Fill the secrets** it prompts for (`sync: false` keys):
   - `LLM_API_KEY` — Google AI Studio key for Gemini.
   - `STANDALONE_ACCESS_CODE` — the password you will give the audience. Required: with
     `REQUIRE_ACCESS_CODE=true` (and automatically on Render) the app refuses to boot
     without it, and `/auth/login` rejects any password that is not exactly this code.
   - `DHIS2_SERVICE_ACCOUNT_PASS` — `district` for the public play instances.
   - `JWT_SECRET` is generated by Render.
4. **Deploy** and wait for the health check (`/health`) to pass. First boot syncs
   DHIS2 metadata (~25 s). Open the URL, log in with any username + the access code,
   and check the header dot is **Live**.
5. **Before the demo:** the free plan sleeps after ~15 min idle and takes ~1 min to wake.
   Open the URL 5–10 minutes before you present and run one suggested question.

Equivalent manual settings (New → Web Service, if you don't use the Blueprint):

| Setting | Value |
| --- | --- |
| Runtime | Docker (Dockerfile path `./Dockerfile`, context `.`) |
| Instance type | Free |
| Build / start | from the Dockerfile; it starts `uvicorn backend.main:app --host 0.0.0.0 --port $PORT --workers 1` |
| Health check path | `/health` |

Native Python runtime (no Docker) also works if you prefer: build command
`pip install -r backend/requirements.txt && cd frontend && npm ci && npm run build`,
start command `uvicorn backend.main:app --host 0.0.0.0 --port $PORT --workers 1`.
PDF export then depends on Render's image having Pango; the app falls back to a
plain PDF if it does not.

Run the same image locally:

```bash
docker build -t dhis2-analyst .
docker run --rm -p 8000:8000 --env-file .env dhis2-analyst
```

## Privacy Defaults

- No LLM or Tavily request is made by default.
- `LLM_PROVIDER=mock` uses deterministic local logic.
- Web enrichment is opt-in per request and disabled unless `TAVILY_API_KEY` is configured.
- Direct SQL is disabled unless `ENABLE_DIRECT_SQL=true`.
- Logs use session/user context and do not log secrets.
